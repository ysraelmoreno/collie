Origem dos dados

Chat = transcript JSONL + hooks do Claude Code. A tela (parse do PTY) só serve de fallback e para o modo Terminal.

Transcript~/.claude/projects/…/<sessão>.jsonl: mensagens, tool_use/tool_result, diffs do Edit. Estruturado, retomável, já indexado pelo daemon (memória). HooksPreToolUse/PermissionRequest → cartão de permissão; Notification → "espera você"; Stop → ocioso. O Collie já usa hooks para o badge. TelaParse de ANSI para detectar diálogos é frágil (muda a cada versão da TUI). Só para presets sem transcript (shell, Cursor) e como rede de segurança.

Resposta no chat = texto injetado na TUI, exceto permissões e perguntas: viram a tecla/opção do diálogo (a armadilha "texto vira a resposta do diálogo" da memória).

Como o agente pede um bloco

A. Fence no texto (zero setup, vale em qualquer agente):

```collie-ui
{"type":"table", …}
```

B. Tool MCP ui.render (collie ui render --json - na CLI): devolve um blockId; permite atualizar o bloco (ui.update) e receber a ação do usuário como resultado da tool.

Tipos v1: table diff tasks chart ask kv. JSON validado por esquema; desconhecido ou inválido cai em bloco de código normal. Sem HTML/JS do agente no chat.

Ponte com Apps do cercado

"⊞ Anexar como painel" = collie app attach com o bloco virando um painel vivo: o JSON do bloco vira ui/index.html mínimo e o app lê os dados por window.collie.state. Passa pelo cartão de aprovação do cercado (agente escreve, usuário aprova).

Inverso: eventos do app (kube.pod.crashed) entram na conversa como bloco rotulado "dado do app", nunca como fala do usuário.

Decisões em aberto

  • Chat como padrão do nó Claude, ou opt-in por terminal?
  • Escrever no chat com TUI em diálogo: bloquear o compositor ou enfileirar?
  • Fence (A) basta na v1, ou já a tool (B) para atualizar blocos?
  • Painel anexado fica estático (snapshot) ou ligado à fonte (work log, API)?
  • Nó pequeno (< 420 pt): chat compacto sem cabeçalho dos blocos?
  • Presets sem transcript (shell, Cursor): só Terminal, sem alternador?
