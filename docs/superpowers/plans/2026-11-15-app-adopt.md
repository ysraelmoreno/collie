# `collie app adopt` Implementation Plan (fase 1)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `collie app adopt` liga uma ferramenta local que já existe ao cercado como um App comum, sem o dono escrever manifesto, e o agente passa a usá-la por tools e avisos.

**Architecture:** `adopt` só gera um `collie-plugin.json` v2 em `.collie/apps/<id>/` (e levanta o cartão de aprovação). Tudo o que vem depois (aprovação, pin, supervisão, SSE, `confirm`) é o que as fatias 1–5 dos Apps já fazem. Três campos novos e opcionais no manifesto cobrem o que a ferramenta de analytics precisa: `service.cwd`, `commands[].result` (`pick`/`tail`) e `eventDiff`.

**Tech Stack:** Swift 6 (SwiftPM), Swift Testing. Módulos `CollieCore` (manifesto), `CollieProtocol` (comandos), `CollieDaemonKit` (daemon), `CollieApp` (cartão).

**Spec:** `docs/superpowers/specs/2026-11-15-app-adopt-and-generative-ui-design.md` (fase 1). Spec dos Apps: `docs/superpowers/specs/2026-11-08-paddock-apps-design.md`.

## Global Constraints

- Só loopback em `service.base` (`127.0.0.1`, `::1`, `localhost`); nunca outro host (`PluginManifest.loopbackOrigin`).
- O agente nunca aprova um app. `adopt` termina no cartão de aprovação.
- Manifesto ≤ 256 KiB; resposta de comando ≤ 1 MiB (`PaddockApps.bodyCap`); evento SSE ≤ 64 KiB (`pluginEventPayloadCap`), exceto o documento de um stream com `eventDiff` (ver Task 4).
- Dados vindos da ferramenta são "dados do app", nunca instrução.
- Escrever só em `.collie/apps/<id>/`. Comandos de escrita (`POST`/`PUT`/`DELETE`) descobertos por OpenAPI nascem com `confirm: true`.
- Testes: só os novos, por `--filter`, nunca a suíte inteira. Sem push. Sem instalar/reiniciar o app nem `bundle-app`. Commits só com os próprios arquivos e o trailer `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- Textos de UI e mensagens ao usuário em pt-BR; erros de protocolo em inglês, como os de `app.new`.

## Review Focus

1. `--cwd` com `..`, caminho absoluto ou link simbólico que sai do cercado: recusado, nada é escrito (Task 2 e 5).
2. Log de analytics limpo (`POST /api/clear/analytics`) ou array que encolhe: o diff reinicia a base e não reemite nem deixa de emitir os itens seguintes (Task 4).
3. Primeiro documento depois de conectar o SSE: só vira base; os eventos antigos não viram uma enxurrada de avisos (Task 4).
4. `adopt` repetido com os mesmos parâmetros não muda o arquivo nem levanta novo cartão; com parâmetros diferentes recusa (`conflict`) sem sobrescrever (Task 5).
5. Resposta de `events` enorme (documento inteiro da ferramenta): `result.pick`/`tail` a reduzem, e uma chave ausente no JSON não derruba o comando (Task 3).

### Task 4: `eventDiff`

**Files:**
- Create: `Sources/CollieDaemonKit/AppEventDiff.swift`
- Modify: `Sources/CollieDaemonKit/PaddockApps.swift` (`subscribe`)
- Test: `Tests/CollieDaemonKitTests/AppEventDiffTests.swift` (novo), `Tests/CollieDaemonKitTests/PaddockAppsTests.swift` (suíte `PaddockAppEventsTests`)

**Interfaces:**
- Consumes: `PluginManifest.eventDiff`, `eventStream`, `events` (Task 1).
- Produces:
  ```swift
  struct AppEventDiff {
      init(key: String)
      /// The items of `doc[key]` not seen in the previous document; the first call only sets the baseline.
      mutating func newItems(in doc: JSONValue) -> [JSONValue]
  }
  ```

Regras de `newItems`: primeira chamada → `[]` (base). Depois: acha o último item da base no novo array (igualdade profunda, da direita para a esquerda); os itens depois dele são os novos. Último item da base ausente (log limpo ou rotacionado) → a base é substituída e devolve os itens do novo array **só se** ele não for mais curto que a base; array mais curto (limpeza) → `[]` e nova base. Chave ausente ou não-array → `[]` sem mudar a base. Teto de 100 itens por chamada (os mais recentes).

No `subscribe`: com `m.eventDiff != nil`, o evento SSE chamado `document` (ou `message`) é lido como documento, com limite de **4 MiB** (em vez de 64 KiB); cada item novo sai por `onEvent(m.events[0], item)`. Itens individuais acima de 64 KiB são descartados como hoje (`pluginEventPayloadCap`). Streams sem `eventDiff` não mudam.

- [ ] **Step 1: Write the failing tests** em `AppEventDiffTests`: `firstDocumentIsBaseline`, `appendedItemsAreNew` (base [a,b], novo [a,b,c,d] → [c,d]), `clearedLogResetsBaseline` (base [a,b,c], novo [] → [], depois novo [x] → [x]), `shorterWithoutLastResetsQuietly` (base [a,b,c], novo [d] → [] e depois [d,e] → [e]), `rotatedWindowStillFindsTail` (base [a,b,c], novo [b,c,d] → [d]), `missingOrNonArrayKeyKeepsBaseline`, `capsAt100Newest`. Em `PaddockAppEventsTests`, `diffStreamNoticesOnlyNewItems` (servidor de teste empurra três documentos SSE de 100 KiB com itens crescentes; o terminal ligado recebe aviso só dos itens novos do 2º e 3º).
- [ ] **Step 2: Run** `swift test --filter AppEventDiffTests` e `--filter PaddockAppEventsTests` — Expected: FAIL.
- [ ] **Step 3: Implement** `AppEventDiff` e a ramificação em `subscribe`; uma instância de `AppEventDiff` por conexão (reconexão = nova base).
- [ ] **Step 4: Run** os dois filtros — Expected: PASS.
