# `collie work run` (slice 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Shepherd can run a work's tasks unattended: a fresh agent per attempt, a check command that decides "done", retries from a clean worktree.

**Architecture:** A `WorkLoop` engine in the daemon owns the attempt cycle and talks to the world only through a `LoopHost` protocol (summon, ask, dismiss, git, check), so it is tested with a fake host and no PTY. `CommandRouter` implements the host over what exists (`summon`, `AskCoordinator.ask`, `remove`, `GitRunner`, `BoundedProcess`) and adds `work.run` / `work.stop`. Loop state is an optional field of `Work`, persisted by `WorkStore`.

**Tech Stack:** Swift 6, Swift Testing, no new dependency.

**Spec:** `docs/superpowers/specs/2026-11-17-work-run-design.md` (slice 1 only; `/collie:loop` and the panel are slice 2, a later plan).

## Global Constraints

- Agent-agnostic: no code path in the loop names a preset or an LLM. The only per-agent input is `AskResult.source` (`hook` | `idle`).
- A task passes only when: check exit 0 **and** a new commit **and** no tracked file dirty.
- The loop never pushes, lands or creates a paddock.
- `work.run` is Shepherd-only (or the app); it needs the work to be in a paddock.
- The check runs under the attempt terminal's sandbox profile when it has one, never with more access than the agent.
- Nothing is written to `~/.claude`, `~/.cursor` or the repo (patches live under Collie's root).
- Tests: only the created/changed suites, `swift test --disable-sandbox --filter '<Suite>'`. Never the whole suite.
- No push, no `bundle-app`, no install or restart of the app.
- Code comments in English; deliberate shortcuts carry a `ponytail:` comment naming the ceiling.
- Defaults: `tries` 3, `timeout` 3600 s (turn), check timeout 1800 s, failure note = last 40 lines of the check output.

## Review Focus

1. Daemon restarts mid-loop: the work must not show "running" forever → on start, a `running` loop becomes `stopped` (Task 4).
2. The agent switches branch or rewrites history: "new commit" must mean the start commit is an ancestor of HEAD on the same branch, not just `HEAD != before` (Task 3).
3. The check itself dirties tracked files (generated code): dirtiness is judged before the check, and tracked files are restored after it (Task 3).
4. The check never exits: bounded by the check timeout and counted as a failed attempt, not a hung loop (Task 3).
5. The starter's work is closed or its terminal removed mid-loop: the loop stops and the attempt's agent is dismissed (Task 4).

### Task 3: The loop engine

**Files:**
- Create: `Sources/CollieDaemonKit/Work/WorkLoop.swift`
- Test: `Tests/CollieDaemonKitTests/WorkLoopTests.swift`

**Interfaces:**
- Consumes: Task 1's model, `WorkStore.update(_:_:)`, `WorkStore.get(_:)`, `AskResult.Source`, `ProcessResult`.
- Produces:
  ```swift
  /// Everything the loop needs from the daemon. No preset or LLM appears here.
  protocol LoopHost: Sendable {
      /// A fresh agent terminal in `work`'s paddock, as the loop's settings ask. Returns its id.
      func summon(name: String, for work: Work, loop: WorkLoopState) async throws(ProtocolError) -> UUID
      func ask(_ terminal: UUID, prompt: String, timeout: Duration) async throws(ProtocolError) -> AskResult.Source
      /// True while the terminal's agent is in a turn (the daemon's own badge/turn state).
      func working(_ terminal: UUID) async -> Bool
      func dismiss(_ terminal: UUID) async
      func git(_ args: [String], in dir: URL) async throws(ProtocolError) -> ProcessResult
      /// `command` via `/bin/bash -c` in `dir`, under `terminal`'s sandbox profile when it has one.
      func check(_ command: String, in dir: URL, terminal: UUID, timeout: Duration) async throws(ProtocolError) -> ProcessResult
      func readSpec(_ path: String) async -> String?
      /// Where attempt patches go: `<root>/work-loops/<work id>/`.
      func patchDir(_ work: UUID) -> URL
      func now() -> Date
  }

  actor WorkLoop {
      init(store: WorkStore, host: any LoopHost, poll: Duration = .seconds(15), checkTimeout: Duration = .seconds(1800))
      /// Runs `work`'s open tasks until all are done/deferred, `max` is used or `stop` is asked. `work.loop` must be set
      /// and `.running`. Returns the final state.
      func run(work id: UUID, dir: URL) async -> WorkLoopState.State
      /// Ends the loop after the current attempt's verdict.
      func stop(work id: UUID)
      static func prompt(task: WorkTask, spec: String?, attempt: Int, tries: Int, dir: URL, notes: [WorkNote]) -> String
      static func verdict(checkStatus: Int32?, committed: Bool, dirty: Bool) -> String?   // nil = pass, else the reason
  }
  ```
- Attempt cycle (the algorithm the signatures do not fix):
  1. First task with `state == .open`. Set it `.inProgress`; `loop.task`, `loop.attempt = (task.tries ?? 0) + 1`, `loop.used += 1`; append a running `WorkJob(id: "loop-<task id>-<n>", kind: .loop, label: task.title)`.
  2. `before = git rev-parse HEAD`, `branch = git rev-parse --abbrev-ref HEAD`.
  3. `summon(name: "loop-<task id>-<n>")`, then `ask` with `prompt(...)` and the loop's timeout. A `summon` error is a failed attempt with that message (no check run). An `ask` timeout goes on to step 5 (the check decides); any other `ask` error is a failed attempt with that message.
  4. **End of turn, for any agent:** if the ask's source is `.hook`, go on. If it is `.idle` and there is no new commit yet, poll every `poll` until there is a commit and `working` is false, or the timeout since the attempt started. A timeout is not a failure by itself.
  5. `committed` = `git merge-base --is-ancestor <before> HEAD` exits 0 **and** `HEAD != before` **and** the branch is still `branch`. `dirty` = `git status --porcelain --untracked-files=no` not empty.
  6. Run the check (even when 5 already fails, so the note has its output). A check that hits `checkTimeout` has status `nil`.
  7. After the check: `git reset -q --hard HEAD` when not dirty before it (the check's own edits never count and never leak into the next attempt).
  8. `verdict(...)`. Reasons, joined by `; `: `check failed (exit N)` / `check timed out`, `no new commit`, `tracked files left dirty`.
  9. **Pass:** task `.done`, `tries = n`, job `.finished` with `result` = short HEAD; dismiss the agent.
     **Fail:** `tries = n`, `lastFailure` = reason; a note `"[loop] <task title>, tentativa n/N: <reason>"` + the last 40 lines of the check output; `git add -A`, `git diff --cached <before>` written to `patchDir/<task id>-<n>.patch`, `git reset -q --hard <before>`; job `.finished` with the reason. Dismiss the agent, except on the task's last attempt (kept for the owner). When `n >= tries`: task `.deferred`, `reason` = `"loop: <reason>"`; else back to `.open`.
  10. Stop when: no open task (`finished`), `loop.max` reached (`stopped`), `stop` was asked (`stopped`), or the work is closed/missing (`stopped`, agent dismissed). Set `loop.state`, `loop.endedAt`, `loop.task = nil`.
- Prompt (Portuguese, the owner's language; fixed text, values interpolated):
  ```
  Tarefa "<title>", tentativa <n> de <N>, num laço autônomo: ninguém vai responder perguntas, então decida e registre a decisão no commit.
  Trabalhe só em <dir>. Faça só esta tarefa. Não faça push nem land.
  Faça commit assim que código e testes estiverem escritos, ANTES de rodar build ou teste: sem commit novo a tarefa não conta. Se depois corrigir algo, faça outro commit. Não deixe arquivo modificado sem commit.
  Depois do seu turno, o laço roda este comando em <dir> e só ele decide se a tarefa passou:
  <check>
  <"O que falhou nas tentativas anteriores:" + the work's "[loop] <title>" notes, when any>

  <spec file's text, or the task title when there is no spec>
  ```

  - no open task
  - an open task without a check → names the tasks
  - a loop already `running` on this work, or on another work of the same paddock
  - another agent terminal of the paddock is working (the caller and Shepherds do not count) → names it
  - tracked files dirty in the paddock's worktree
- When the loop ends, the starter gets one line through the existing inject path (`asks.inject(to:prompt:afterQuiet: true)`): `[collie] Laço de "<work title>" terminou: <done> feitas, <deferred> adiadas. Veja: collie work status`.
