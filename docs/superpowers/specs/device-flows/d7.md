# d7: Passo destrutivo precisa de confirmação

Spec da tarefa d7 do laço dos fluxos do device. Design: `docs/superpowers/specs/2026-11-26-device-flows-design.md` (leia a seção da onda). Check: `scripts/check-device-flows.sh d7` (não o altere). Testes novos sem relógio real nem sleep; só `swift test --filter`.

## O que construir
- Passo com `destructive: true` **não executa** sem confirmação do usuário. Nesta tarefa a confirmação é o flag `--confirm-destructive`, que **só o usuário pelo app/CLI de admin** pode passar: terminais de agente nunca (o daemon recusa o flag vindo de agente com o mesmo critério dos comandos de admin). O cartão no app fica fora desta tarefa (anote em `Resultado` do spec o que falta).
- A recusa para o plano antes de executar qualquer passo posterior e devolve `{refused:"destructive", at:<passo>}`.
## Critérios de aceite (testes em `FlowDestructiveTests`, ≥ 5)
- Plano com passo destrutivo vindo de agente é recusado nesse passo; passos anteriores já executados continuam executados e relatados.
- O flag vindo de agente é recusado. Vindo do admin, executa. Plano sem passo destrutivo não é afetado.

## Resultado
- `FlowRunner(confirmed:)`: um passo `destructive: true` sem confirmação para o plano antes dele e devolve `{ok:false, refused:"destructive", at:<passo, 1-based>, done:<passos já executados>}`; os anteriores ficam executados.
- `--confirm-destructive` (`device.run`): o daemon só aceita sem `terminalId` e depois do `adminOnly` (via `principal`), o mesmo critério dos comandos de admin; vindo de terminal de agente (CLI ou MCP) é `unauthorized`, antes de ler o plano. Decisão (laço autônomo): o flag vindo de agente é erro, não "ignorado", para o agente não achar que confirmou.
- Falta: o cartão no app que pergunta ao usuário quando um plano de agente para em `refused:"destructive"` e roda o resto com a confirmação (hoje o usuário roda de novo `collie device run --plan … --confirm-destructive` fora de um terminal, o plano inteiro desde o início).
