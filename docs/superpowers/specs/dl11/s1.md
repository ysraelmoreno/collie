# S1: o daemon confere que o helper instalado é o embutido

Contexto: o helper agora é assinado com uma chave privada do publicador (Helpers/android-device/README.md, seção Assinatura; Resources/collie-helper.apk). Um APK com o mesmo pacote mas outra assinatura ou outros bytes (a chave debug é pública) não pode ser aceito como o helper oficial. Faça SÓ isto e COMMITE ao final (git add por caminho + git commit); não edite Resources/ nem scripts/.
Em DeviceHelper, ao preparar um dispositivo (e na escada de recuperação), antes de confiar no helper já instalado: obtenha o SHA-256 do APK instalado (`adb shell pm path com.collie.helper` para o caminho do base.apk e `adb shell sha256sum <caminho>`; o toybox do Android tem sha256sum) e compare com o SHA-256 do APK embutido, calculado no host (CryptoKit, no APK que o provedor injetável já entrega). Se for diferente: reinstale o embutido (a K1b já desinstala e reinstala quando a assinatura mudou), habilite e confirme com dump com nós, e registre o motivo em `device helper status` ('installed helper differs from the bundled one'). Mesma versão e mesmos bytes: nada a fazer. Se `sha256sum` não existir ou falhar: não bloqueia, segue como hoje e o status diz 'could not verify the installed helper'. A palavra sha256 deve aparecer em Sources/CollieDaemonKit/Devices/DeviceHelper.swift.
Testes DeviceHelperTests com adb falso: bytes iguais não reinstala, bytes diferentes reinstala uma vez e o status diz o motivo, sha256sum ausente não bloqueia, lista de serviços alheios preservada.
Regras: só --filter; não rode a suíte completa. O check é `scripts/check-device-loop11.sh s1` e o gate roda depois.
