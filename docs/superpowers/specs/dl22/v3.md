# V3: o Collie grava sozinho a confiança da pasta dos revisores

Medido em 2026-11-23: o revisor nasce em pasta aleatória sob `~/Library/Application Support/Collie/collie-review/` (`reviewRoot`, `mkdtemp`) e o Claude
Code pede "trust this folder" a cada revisão. Só o usuário responde esse diálogo (decisão `81effa13`): sem resposta o revisor fica "sem resposta".
Gravar `projects["<reviewRoot>"].hasTrustDialogAccepted = true` em `~/.claude.json` resolveu: a confiança da pasta-mãe vale para as subpastas
(isca f2e sem diálogo). Hoje isso está só na máquina do dono, gravado à mão.

Fazer: no início de um `work run --review` (e só com `--review`), antes de tirar a base do hash de `~/.claude.json` (`reviewLoopConfigBase`), garantir
que a entrada do `reviewRoot` existe com `hasTrustDialogAccepted: true`. Regras:
1. Leitura, mesclagem e escrita atômica (arquivo temporário no mesmo diretório, `rename`), preservando todo o resto do arquivo, as permissões e a
   ordem não importa; nunca sobrescrever uma entrada existente além desse campo; se o arquivo não existe, não criar (o Claude Code ainda não rodou);
   se não é um objeto JSON, não tocar e seguir (o revisor segue "sem resposta" e a nota diz por quê).
2. Só grava quando o campo ainda não é `true` (idempotente; a segunda execução não regrava).
3. A base do hash é tirada DEPOIS da gravação, para que a gravação não conte como "mudou durante a tentativa"; deixe uma nota do laço
   ("confiança da pasta dos revisores gravada em ~/.claude.json") quando gravar.
4. Falha de escrita não derruba o laço: a nota diz o motivo e o `--review` segue como hoje.
