# K1: chave de assinatura privada do helper (script e docs)

Hoje scripts/build-device-helper.sh assina com Helpers/android-device/helper.jks, uma chave debug PÚBLICA (senha android) commitada no repositório. Antes de distribuir o helper é preciso uma chave privada fora do repo. Mude o script: (1) `--help` imprime o uso e sai com 0 antes de procurar SDK ou JDK. (2) Escolha da chave: COLLIE_HELPER_KEYSTORE (caminho) com COLLIE_HELPER_KEY_ALIAS (padrão collie-helper); a senha vem de COLLIE_HELPER_STOREPASS ou, no macOS, do item genérico do Keychain 'collie-helper-keystore' (security find-generic-password -w); nunca por argumento de linha de comando nem escrita em log. (3) Sem COLLIE_HELPER_KEYSTORE usa a chave debug do repo e imprime em stderr 'AVISO: chave DEBUG pública, só para desenvolvimento; não distribua este APK'. (4) `--release` recusa a chave debug (sai com 1 e diz como gerar uma). (5) `--genkey <caminho>` cria um keystore privado (RSA 4096, validade 36500 dias, permissão 0600, fora do repo: recusa caminho dentro do repositório) e imprime como guardar a senha no Keychain; sem sobrescrever um existente. README do helper: seção 'Assinatura' com o fluxo (genkey, Keychain, build --release) e o aviso de que trocar a chave quebra o install -r em aparelhos que já têm o helper assinado com a debug (a K1b trata isso no daemon). Em teste, o script não pode precisar do SDK: o --help e as recusas acontecem antes.
