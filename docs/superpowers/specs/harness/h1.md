# h1: seção `harness` do collie-work.json, lida de forma estrita

Primeira tarefa de laço da harness fora de laço (design em `docs/superpowers/specs/harness/design.md`; leia o resultado do spike em `spike-report.md` antes, ele diz que modos cada agente realmente suporta). Check: `scripts/check-harness.sh h1` (não o altere). Sem relógio real nem sleep; só `swift test --filter`.

## O que construir (CollieCore, puro: lê bytes, não lê arquivo nem roda comando)
- `ProjectWorkConfig` ganha `harness: HarnessConfig?` (nil sem a chave). Parser estrito como o resto: tipo errado, modo inválido, comando fora dos limites e chave desconhecida **dentro** de `harness` são erro (ou aviso, como `fields`: escolha igual ao padrão do arquivo e documente); a chave de topo continua com os limites do arquivo (16 KB no total).
- Forma (nomes exatos):
  - `precheck`: comando opcional (o mesmo limite de comando do arquivo).
  - `edit`: lista de `{paths: [glob], run: comando, mode, timeout}` (máx 10 regras, 10 globs cada).
  - `turnEnd`: `{run: comando | "areas", mode, timeout}`.
  - `commit`: `{run: comando | "gate", mode}` (aplicado pelo hook de git; `mode` `advisory|ask|block`).
  - `guardrails.deny`: lista de `{match, mode, message?}` (máx 40); `guardrails.protect`: lista de globs (máx 40); `guardrails.requireBefore`: lista de `{match, check}` onde `check` é `gate`, `smoke` ou o nome de uma área existente (nome desconhecido é erro com a lista das áreas, como `unknownArea`).
- Modos: `advisory | ask | block`. `timeout` em segundos, inteiro de 1 a 600 (padrão por camada nomeado: edit 5, turnEnd 120). Mensagens de erro em português, uma linha, sem eco bruto do arquivo (quem mostra limpa).
- Comandos de `edit`/`turnEnd`/`commit` seguem a regra dos outros comandos do arquivo (sem quebra de linha, ≤ 1000); `match` é um padrão (não um comando): ≤ 200 caracteres, sem controle.
- Sem `harness`, nada muda para quem não usa (todos os testes antigos passam).
## Critérios de aceite (testes em `HarnessConfigTests`, ≥ 16)
- Arquivo mínimo com `harness` vazio `{}`: válido, tudo nil/padrão.
- Exemplo completo (o do design) parseia. Cada modo inválido, timeout 0/601/não inteiro, `paths` vazio, `check` desconhecido, regra a mais que o máximo, `match` longo, chave de topo desconhecida dentro de `harness`: erro específico.
- `requireBefore.check` aceita `gate`, `smoke` e uma área; recusa o resto com a lista de áreas.
- O arquivo total ainda respeita 16 KB. `ProjectWorkConfigTests`, `FactoryProfileTests` e `WorkConfigTamperTests` continuam passando.
