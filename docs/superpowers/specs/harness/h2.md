# h2: casador de comandos dos guardrails (`deny`/`requireBefore`), puro e à prova de contorno

Depende da h1. Check: `scripts/check-harness.sh h2` (não o altere). Sem relógio real nem sleep; só `swift test --filter`.

## O que construir (CollieCore, puro)
- `HarnessMatcher.evaluate(command: String, config: HarnessConfig, checkPassed: (String) -> Bool) -> HarnessVerdict` onde o veredito é `allow` | `advisory(message)` | `ask(message)` | `block(message)` e carrega a regra que bateu.
- O comando é **dividido em segmentos** (`&&`, `||`, `;`, `|`, `&`, quebra de linha, `$(...)` e crases, `bash|sh|zsh -c "..."`, `env VAR=x cmd`, `command cmd`, `sudo cmd`, `time cmd`, `xargs cmd`) e **cada segmento** é casado; vale o veredito mais severo (`block` > `ask` > `advisory` > `allow`). Palavras são normalizadas (espaços múltiplos, aspas simples/duplas ao redor de argumentos, `git  push`, `git -C dir push`, `git -c k=v push`, alias por caminho `/usr/bin/git`), e `match` é um glob sobre o **comando normalizado** (`git push*`).
- **Fail-closed:** comando que não dá para analisar (aspas abertas, expansão profunda demais, > 4 KB, caractere de controle) devolve o veredito da regra `block` mais severa se houver alguma regra `block`, senão `ask`.
- `requireBefore`: um segmento que bate com `match` só é `allow` se `checkPassed(check)` for true; senão vira `block` com a mensagem "rode <check> antes".
- `protect`: `HarnessMatcher.protects(path:, config:)` para caminhos de escrita (`Edit`/`Write`/redirecionamento `>`/`tee`/`sed -i`/`mv`/`rm` em um segmento), com caminhos normalizados (`..`, `./`, symlink não resolvido aqui: o chamador passa o caminho real).
## Critérios de aceite (testes em `HarnessMatcherTests`, ≥ 20)
- `git push` direto, `git  push`, `git -C x push`, `/usr/bin/git push`, `env X=1 git push`, `sh -c "git push"`, `echo ok && git push`, `true; git push`, `git push | cat`, `$(git push)`: todos batem com `deny "git push*"`.
- `git status` e `echo "git push"` (argumento, não comando) não batem.
- Comando não analisável cai no fail-closed. Severidade máxima entre segmentos. `requireBefore` com e sem o check passado.
- `protect`: `Edit` em `scripts/ci/lint.sh`, redirecionamento `> scripts/ci/x.sh`, `sed -i` e `rm` batem; `Sources/x.swift` não.
- `HarnessConfigTests` continua passando.
